# 게임 시스템 스펙 (로케테스트 기준)

이 문서가 게임 규칙의 정답이다. 숫자는 모두 `[SerializeField]` 기본값으로 넣고, 사용자가 인스펙터에서 조정한다.
"(조정값)"이라고 적힌 숫자는 테스트로 바뀔 값이니 특히 하드코딩하지 않는다.

## 0. 로케테스트 사양

- 한 PC, 게임패드 2개, 화면 분할(좌우 2분할), 1대1
- 버나드 표준형(PSX-0001) 미러전. 두 기체는 같은 컴포넌트 구성
- 3판 2선승. 장갑(HP)이 0이 되면 그 라운드 패배
- 버나드 계열은 **원거리 무기가 없다.** 모든 공격은 펀치, 몸통, 스러스터, 앵커 클로, 파일드라이버
- 빠지는 것: 다른 기체, 정지 후 마무리 선택, 테더, 중력 단계 등 스토리 모드 시스템

## 1. 자원

### 부스트 (몸을 움직이는 자원)

| 항목 | 규칙 |
| --- | --- |
| 소모 | 전력질주(초당), 슬라이딩, 사이드스텝, 초신지선회, 스러스터 런지 |
| 회복 | 걷기·정지(Idle) 중에만, 회복 지연 후 차오름. **가드를 올리고 있으면 회복이 멈춘다** |
| 유지 | 달리기 중에는 소모도 회복도 없다 |
| 0% = 탈진 | 이동 속도 저하, 특수 기동과 런지 봉쇄. **걷기/정지로 회복해 50%(조정값)에 도달하면 해제** (현재 코드는 100%) |
| 가드 | 가드는 부스트를 쓰지 않는다 |
| 총량·소모량 | 사용자가 직접 조정 (조정값) |

### 히트 (주먹을 쓰고 막는 자원)

| 항목 | 규칙 |
| --- | --- |
| 오르는 때 | 펀치 한 방당 6% (조정값, 5~7 범위), 가드로 공격을 막을 때마다 10% (조정값) |
| 안 오르는 행동 | 런지, 어깨 태클/대시 어택, 스킬, 패리 |
| 냉각 | 저절로 식는다. 전력질주 중에는 냉각 효율이 크게 떨어진다 (기본: 냉각 속도 30%, `sprintCoolingReduction` 0.7) |
| 100% = 과열 | 펀치를 쓸 수 없다. **0%까지 식어야 해제** |
| 과열 중 가드 | 과열 상태에서 가드로 공격을 받으면 **가드 깨짐**: 가드가 풀리고 0.9초(조정값, 0.8~1.0) 무방비(스턴) |

### 속도 단계별 정리

| 단계 | 부스트 | 히트 냉각 | 역할 |
| --- | --- | --- | --- |
| 걷기 (L스틱 80% 미만) | 회복 | 정상 | 숨 고르기 |
| 달리기 (L스틱 80% 이상) | 유지 | 정상 | 거리 재기 |
| 전력질주 | 소모 | 급감 | 돌격, 태클 |

## 2. 기동

| 기술 | 패드 입력 | 사용 상태 | 부스트 | 효과 |
| --- | --- | --- | --- | --- |
| 걷기/달리기 | L스틱 (80% 경계) | — | — | 기존 구현 유지 |
| 전력질주 | 달리기 중 R스틱을 L스틱과 같은 방향으로 꺾기 (E6) | 달리기에서 | 초당 소모 | 최고 속도, 선회력 저하, 가드 불가, 기본 공격이 대시 어택. 1.5초부터 태클 차징 |
| 정지 | L스틱 중립 | 전부 | 없음 | 관성으로 살짝 미끄러지며 제동 (Brake) |
| 슬라이딩 | 전력질주를 스틱을 놓아 끝낸 뒤 0.2초 안에 L스틱 ↗ + R스틱 ↖ (E6) | 전력질주 | 사용 | 상대의 락온을 강제로 해제, 바라보는 방향으로 미끄러짐 |
| 초신지선회 | L스틱 ↓ 튕기기 | 걷기·달리기·전력질주 | 사용 | 즉시 180° 회전 |
| 사이드스텝 | L스틱 ← / → 튕기기 | 걷기·달리기·전력질주 | 사용 | 즉시 옆으로 짧게 이동 |

- "튕기기" = 스틱을 중립 근처(크기 < 0.3)에서 0.15초 안에 해당 방향 끝(크기 > 0.8)까지 밀었다가 놓는 동작. 임계값과 시간은 SerializeField.
- 키보드 바인딩(Space, Ctrl, R, A/D 더블탭 등)은 디버그용으로 남겨도 되지만 반드시 InputReader 안에서만 처리한다.

### 전력질주·슬라이딩 두 스틱 조작 (E6 결정)

왼쪽 스틱 = 방향, 오른쪽 스틱 = 가속. 방향 비교는 두 스틱의 원래 입력 벡터끼리 한다(카메라 무관). 수치는 전부 `BernardTuning → 이동`.

- **진입**: 달리기 상태(L스틱 80% 이상)에서 R스틱이 중립(크기 < 0.3)을 벗어나 **0.15초 안에** 크기 0.8 이상이 되고, 그 순간 두 스틱 방향 차이가 **20° 이하**.
- **유지**: 두 스틱 모두 0.8 이상이고 방향 차이 20° 이하인 동안.
- **해제**: 방향 차이 20° 초과 → 바로 제동 (단 아래 "안쪽 굴리기"는 예외). L스틱을 놓음(0.8 미만) 또는 R스틱을 놓음(0.8 미만) → "스틱 중립 해제". 부스트 탈진 → 제동(기존 규칙).
- 전력질주 중 R스틱은 카메라 입력으로 쓰지 않는다(카메라는 진행 방향을 따라감).
- (F2) 진입 판정 중(R스틱이 중립을 벗어나 0.15초 판정이 끝나기 전)에도 R스틱을 카메라에 안 쓰고 진행 방향을 따라간다. 질주가 풀린 뒤에도 R스틱이 중립(0.3 미만)으로 한 번 돌아올 때까지 카메라 회전 입력을 막는다.
- (F2) 유지 해제 조건(각도 초과·스틱 크기 미달·스틱 놓음)은 0.1초(`sprintExitConfirmTime`) 이상 이어져야 해제. 유지 스틱 크기 기준(`sprintHoldStickThreshold`)은 진입 기준과 별도 값(기본 둘 다 0.8). 각도는 두 스틱 원래 값끼리만 비교한다.
- **슬라이딩**: "스틱 중립 해제" 직후 **0.2초** 동안은 제동으로 넘어가지 않고 대기(추진 없이 관성 이동). 이 안에 L스틱 ↗(45° ± 25°)와 R스틱 ↖(135° ± 25°)가 둘 다 0.8 이상이면 슬라이딩, 안 들어오면 그때 제동. 각도는 오른쪽 = 0°, 위 = 90°. 방향 차이로 풀린 경우엔 대기가 없다 — 예외: **안쪽 굴리기**(E6.1). 마지막 유지 방향 기준으로 L스틱은 시계 방향(↗ 쪽), R스틱은 반시계 방향(↖ 쪽)으로 둘 다 돌며 벌어져 풀렸으면 중립 해제와 같은 0.2초 대기를 건다(이미 ↗/↖에 닿아 있으면 그 자리에서 슬라이딩). 한쪽만 돌았거나 다른 방향으로 벌어지면 바로 제동.
- 슬라이딩 방향은 기체 진행 방향(기존과 같음), 상대 락온 해제 0.8초도 그대로.
- 초신지선회(L ↓ 튕기기)·사이드스텝(L ←/→ 튕기기)·키보드(Space 질주, Ctrl 슬라이딩)는 그대로. 패드 L3 질주 바인딩은 E6.1에서 삭제. 예전 L스틱 ↑↑ 질주, L스틱만 쓰는 ↗/↖ 슬라이딩은 없앴다.

## 3. 조준

화면 분할이라 모든 기준은 **각자 자기 카메라, 자기 기체, 자기 상대**다. 락온 버튼은 없다.

| 단계 | 걸리는 조건 | 하는 일 | 풀리는 조건 |
| --- | --- | --- | --- |
| 소프트 락온 | 자기 카메라 정면 30° 원뿔 안, 50m 안, 레이캐스트로 가려지지 않은 상대 | 상대를 목표로 잡는다. 앵커 클로·투사체가 이 목표를 쓴다. 카메라는 안 움직임 | 원뿔 밖, 가려짐 |
| 하드 락온 | 소프트 락온 상대가 **기체 위치 기준** 6m 안 | 카메라가 상대를 추적(추적 속도 5). 기본 공격이 펀치로 전환 | 기체 기준 7m 밖, 정면 ±60° 밖, 상대의 슬라이딩, 내 런지 돌진 중 |
| 소프트 호밍 | 투사체 비행 중 | 각도 점수(30° 기준)와 거리 점수(50m 기준)의 평균으로 유도 | 투사체가 상대를 지나침 |

- 현재 코드는 하드 락온 거리를 카메라 위치에서 잰다 → 기체 위치로 고친다. 진입값 기본 6m.
- **하드 락온 중에는 기체 몸통이 상대 방향으로 자동으로 돈다.** 수평 회전만 하고, 회전 속도는 SerializeField(`MechController.hardLockTurnSpeed`). 전력질주·런지·슬라이딩·초신지선회 중에는 적용하지 않는다. (A9 추가)
- 소프트 호밍은 버나드 미러전에서 쓰이지 않는다. 코드는 지우지 말고 남긴다 (사격 기체용).

## 4. 기본 공격 버튼 (공격 버튼 하나, 위에서부터 우선)

| 우선 | 조건 | 나가는 것 |
| --- | --- | --- |
| 1 | 앵커 클로로 끌어온 직후(파일드라이버 준비 상태) | 파일드라이버 |
| 2 | 전력질주 중 | 대시 어택(어깨 태클) |
| 3 | 하드 락온 중 (상대 6m 안) | 너클 펀치 |
| 4 | 그 외 (상대 6m 밖 또는 락온 없음) | 스러스터 런지 |

버나드 계열에서 사격(`TryFire`)은 호출되지 않는다. 기체마다 "원거리 모드"를 고를 수 있게 하고(enum: `Lunge`, `Projectile`), 버나드는 `Lunge`.

### 입력 규칙 (E4.1 결정)
- 공격(펀치·런지·대시 어택·태클·파일드라이버)은 **버튼을 누른 프레임에만** 나간다. 누르고 있기만 하면 아무것도 나가지 않는다(연타·런지 후 자동 후속타 없음).
- **입력 버퍼 0.15초(조정값 `inputBuffer`)**: 지금 못 나가는 공격 — 쿨다운, 발생 시간 중, 런지 돌진 중, 스턴 중 등 — 은 누른 뒤 0.15초 동안 기억했다가 가능해지는 프레임에 발동한다. 즉 막힌 상태가 끝나기 0.15초 전 안에 누른 입력만 살아남고, 그보다 일찍 누른 입력은 버려진다.
- 버퍼된 입력이 무엇이 될지는 **발동하는 프레임의 상황**(위 표의 우선순위)으로 다시 정한다. 예: 누를 땐 하드 락온(펀치)이었는데 발동 때 멀어졌으면 런지.
- 스턴 중엔 어떤 공격도 시작하지 않는다(파일드라이버 포함).
- 라운드 카운트다운·메뉴 중 누른 입력은 버퍼에 남지 않는다.
- 버퍼 시간은 게임 시간 기준이라 히트스톱 동안은 줄지 않는다.
- 연습 봇도 같은 규칙(누른 순간 + 같은 버퍼, 발동 때 하드 락온 거리 안이면 펀치·밖이면 런지).
- 예외: 사격 기체(`Projectile` 모드)의 원거리 사격만 누르고 있으면 연사(버나드 로케 범위 밖).

## 5. 공격

### 공격 발생 시간 (E4 결정)
- 버튼을 누르면 **예비 동작**이 시작되고, **발생 시간**이 지난 프레임에 판정한다. 상대가 예비 동작을 보고 읽을 수 있게 하기 위함.
- 발생 시간(조정값): **펀치 0.1초, 대시 어택 0.12초, 차징 태클 0.1초.** 0이면 예전처럼 누른 프레임에 즉시 판정(끌 수 있음).
- 판정 범위(사거리·부채꼴)와 상대 위치는 **판정하는 순간** 기준이다.
- 쿨다운·히트 증가·"발동" 집계는 버튼을 누른 순간 기준.
- 발생 시간 도중 **스턴이나 가드 깨짐**을 당하면 그 공격은 취소된다(쿨다운은 이미 쓴 것으로). 스턴 중엔 새 펀치를 시작할 수 없다.
- 어깨 태클은 발생 시간 동안 질주 방향 그대로 밀고 나가며(제동·퀵턴·사이드스텝 전환 없음), 판정 후 멈춘다.
- 런지는 돌진 자체가 이동 시간이라 발생 시간을 따로 두지 않는다.

### 너클 펀치
- 피해 25 (조정값), 쿨다운 0.5초, 사거리 3m.
- **판정은 기체 정면 부채꼴(기본 ±45°)만.** 상대 하나(자기 상대 참조)만 맞는다.
- 한 방당 히트 +6%. 과열 중엔 나가지 않는다.

### 스러스터 런지 (신규)
- 발동: 4번 우선 조건. 부스트 소모(조정값). 탈진이면 발동 안 함.
- 바라보는 방향(카메라 수평 정면)으로 **일직선** 돌진. 돌진 거리·속도는 SerializeField (기본 8m, 사용자가 테스트로 정함).
- 돌진 중에는 하드 락온·근접 전환·호밍이 없다. 6m 안에 들어가도 방향이 바뀌지 않는다.
- 명중: 피해(조정값, 기본 15 = 펀치보다 약간 낮게) + 상대 **스턴 0.5초**. 스턴 타이머는 히트스톱이 끝난 뒤부터 센다. 이후 후속 펀치 1회가 들어갈 수 있어야 한다.
- 가드를 뚫는다 (가드 감쇄 없음, 가드 히트 증가 없음).
- 패리당하면: 런지한 쪽이 **런지 피해의 100%를 받고** 뒤로 튕겨난다(넉백). 스턴은 없다.
- 빗나가면: 돌진 종료 후 딜레이(기본 0.6초, 조정값) 동안 하드 락온이 다시 걸리지 않는다. 사이드스텝으로 피한 상대가 반격할 틈이다.
- **판정 방식 (M4, 조정값 `Lunge.judgeMode`, 기본 새 방식)**: 돌진 중 상대 중심이 돌진 방향 정면(±45°) **2.5m** 안에 들어오면 그 자리에서 멈춰 **앞발 박기(0.08초, 판정 없음) → 스트레이트 뻗기(0.1초)**. 판정은 뻗는 구간에만(판정 구는 예전과 같은 전방 1m·반경 1.2m). 상대에 못 닿고 돌진(8m)이 끝나면 그 자리에서 같은 박기·헛펀치 후 위 빗나감 처리. 피해·스턴 0.5초·가드 관통·패리 반사는 그대로. 예전 방식(돌진 중 몸이 닿는 순간 명중)으로 되돌릴 수 있다.
- 히트를 올리지 않는다.

### 대시 어택 / 태클
- 전력질주 중 공격 버튼 = 어깨 태클.
- 전력질주 1.5초 미만: 일반 대시 어택. 가드에 막힌다(가드 규칙 적용).
- 전력질주 1.5초 이상(차징 활성): 태클. 가드를 뚫고 스턴. 차징이 길수록(3초에서 최대) 피해·넉백·스턴 증가 — 기존 `TackleChargePower` 계산 유지.
- 기존의 "차징 상태로 상대에 닿으면 자동 발동"은 유지할지 `docs/QUESTIONS.md`에 적고, 기본값은 **유지(버튼 + 자동 접촉 둘 다)**.
- 판정 범위: 기체 정면 ±45°, 5m (B8 결정). 버튼 태클·대시 어택·자동 접촉 태클 모두 같은 부채꼴. 부채꼴 밖이면 버튼 태클은 헛침(멈추고 경직), 자동 접촉은 발동 안 함.
- 패리당하면: 태클한 쪽이 피해를 100% 돌려받고 뒤로 밀려난다. **공격자 스턴은 없앤다** (현재 코드는 0.5초 스턴).
- 히트를 올리지 않는다.

## 6. 방어

### 가드
- 가드 버튼을 누르고 있는 동안. 올리는 비용 없음.
- 펀치·대시 어택·슬램 피해를 **50%** 감쇄 (조정값). 투사체는 70% 감쇄 (사격 기체용, 유지). 파일드라이버는 잡기 후속타라 가드·패리를 무시한다 (A9 결정).
- 가드로 공격을 받을 때마다 히트 +10%.
- 과열 상태에서 가드로 받으면 가드 깨짐 → 0.9초 스턴, 그 공격은 감쇄 없이 들어간다.
- 런지·차징 태클·파일드라이버는 가드를 뚫는다.
- 가드를 내린 뒤 다시 올리려면 **0.4초** 대기 (조정값). 단, **패리에 성공한 직후에는 대기 없음** (후속타 패리 가능).
- 전력질주 중에는 가드 불가 (현재 구현 유지). 스턴 중 가드 불가.
- 가드 중에는 걷기여도 부스트 회복 정지.

### 패리
- 가드를 올린 순간부터 0.15초(현재 `parryWindow`) 안에 맞으면 패리.
- 패리는 모든 공격 피해를 0으로 막고 히트도 안 오른다.
- 런지·태클을 패리하면 공격자가 그 공격 피해를 100% 받고 넉백. 상대를 굳히지는 않는다.
- 패리 성공 직후에는 가드 재사용 대기가 없다.

### 맞딜
- 양쪽 **펀치의 판정 시점이 0.1초(조정값 `clashWindow`) 이내**면 서로 0 피해 + 넉백 (E4에서 변경). 한쪽이 판정될 때 다른 쪽 펀치가 이미 판정됐거나(0.1초 이내), 아직 발생 중이지만 0.1초 안에 판정될 예정이면 맞딜이고, 그 펀치는 맞딜로 소진된다.

## 7. 스킬

| 스킬 | 내용 | 쿨타임 |
| --- | --- | --- |
| 앵커 클로 | 소프트 락온 목표를 끌어옴. **투사체(F1)**: 예비 동작 0.2초(왼팔 당김 + 손끝 발광) → 발사 순간 상대 위치로 일직선 40m/s, 사거리 12m, 유도 없음(사이드스텝·슬라이딩으로 피함). 맞으면 끌어옴, 빗나가면 와이어가 감겨 돌아옴. 직후 공격 버튼으로 파일드라이버(피해 50, 4m 이내) | 5초 (발사 순간부터) |
| 임팩트 슬램 | 전방 90°, 8m 충격파, 피해 60, 넉백. **가드·패리 판정을 적용한다** (현재 무시하는 건 버그) | 8초 |

스킬은 히트를 올리지 않는다. 앵커 클로는 잡기라 가드와 패리를 무시한다. 후속 파일드라이버도 가드·패리를 무시한다(관통 처리, A9 결정).

## 8. 라운드와 매치

- 라운드 시작 시 두 기체 모두 리셋: 위치·회전, 체력, 부스트(최대), 히트(0), 탈진·과열 해제, 스턴 해제, 리지드바디 속도 0, 상태 Idle, 앵커 클로·스킬 쿨타임 초기화, 외부 잠금 해제, 락온 해제, 가드 상태 해제.
- 라운드 시작 카운트다운 3초 (입력 무시) → "FIGHT".
- 라운드 종료 후 3초 뒤 다음 라운드. 매치 종료 시 결과 표시 → 아무 패드의 시작 버튼으로 재매치.
- 동시 사망은 무승부 라운드로 처리하고 다시 진행 (승수 증가 없음).
